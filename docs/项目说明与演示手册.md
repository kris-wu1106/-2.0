# 广西警察学院 · 宿舍智能交付与后勤管理平台
## 项目说明与演示手册（v0.2）

> 对应 PRD：《高校宿舍智能交付与后勤管理平台 PRD v1.2》（赛道二 · FDE 场景交付）
> 技术栈：Vue 3 + Element Plus / Node.js + Express / SQLite（node:sqlite，零原生依赖）
> 在线演示：发布链接见对话卡片 · 本地运行：`cd dorm-platform && npm start` → http://localhost:4321

---

## 一、项目定位

面向高校后勤的「交付即服务」平台：把 FDE（现场交付工程师）的数据治理、规则配置、方案确认、验收归档能力，产品化为宿管可自助完成的标准动作，并与学生、辅导员的日常宿舍业务闭环打通。主线不是「宿舍增删改查」，而是 **七阶段交付链路**：

```
原始数据导入 → 校验清洗 → 规则化分配 → 人工确认锁定 → 日常业务开服 → 交付物导出 → 验收归档（变更单解锁）
```

## 三、本轮按 PRD 新增/补强

1. **学生端业务入口**（PRD 2.2）：「我的宿舍」新增报修、调宿申请弹窗 + 「我的申请记录」进度表；调宿目标房间做性别属性与房间状态前置校验。
2. **分配方案手动微调**（PRD F2）：明细表逐行「调整」，候选床位仅性别匹配的空闲床或方案内床位，方案内选床即**两人对调**；性别、房间状态冲突即时拦截并写审计。
3. **变更单闭环**（PRD 3.4/4.6）：归档后唯一修改通道——提交变更单（归档态仍可提交）→ 宿管批准自动解除只读恢复「日常开服」/ 驳回保持只读，全程审计。
4. **接口权限护栏**（PRD 8.3/2.5 权责矩阵）：学生提交类接口仅 student，审批/执行类仅 admin+counselor，导入/分配/归档/变更单审批仅 admin，越权返回 403。

## 五、数据与环境

- 种子数据：**仙葫校区** 1/2/3（男）、4/5/6/7（女）**7 栋** 252 间房 1512 张床位；**1176 名** 26 级学生，覆盖 14 个专业（侦查学/治安学/刑事科学技术/网络安全与执法/交通管理工程/警务指挥与战术/公安管理学/涉外警务/禁毒学/经济犯罪侦查/数据警务技术/监狱学/法学/行政管理），**每个专业只编 1-2 个区队**，共 **28 个区队**，命名如「26级网络安全与执法1区队」；一个区队 42 人、占 7 间六人间，**一个宿舍整间住同一区队**；6 栋入住率 78%（168/216），7 栋 3 个区队 58%。当前留 1 个区队（42 人）未分床位，用于演示「智能床位分配」。
- 数据库 SQLite 单文件（`server/data/dorm.db`），首次启动自动建表与播种；所有写操作写审计日志（操作人/角色/变更前后值/原因）。
- 隐私边界：学生端室友仅展示姓名；通讯录仅工作电话。
